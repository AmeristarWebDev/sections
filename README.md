# Ameristar Sections

Embeddable page sections for ameristarperimeter.com (AEM / OneCMS), plus the editor used to design them.

**The rule:** AEM owns the page. This repo owns *sections* — self-contained blocks that drop into an AEM Embed component. Each section's *presentation* lives here; its *copy* starts here and moves to the DAM once approved (the "hybrid" model).

```
ameristar-sections/
├── editor/index.html          ← the design/edit app (no build, runs off any static server)
├── sections/
│   ├── index.json             ← registry: which sections exist + hosting URLs
│   ├── _template/             ← copy this to start a new section
│   └── audience-cards/        ← example section
│       ├── section.js         ← renderer + loader + scoped CSS (the thing AEM embeds)
│       ├── index.html         ← standalone preview / iframe host / editor preview target
│       ├── content.json       ← design-time copy
│       └── schema.json        ← tells the editor what fields to show
└── README.md
```

## Running the editor

The editor fetches JSON, so it needs HTTP (not `file://`). From the repo root:

```
python -m http.server 8080
```

then open <http://localhost:8080/editor/>. Pick a section, edit on the left, watch the preview on the right (Desktop / Tablet / Mobile). Edits are saved as a local draft in your browser until you reset or export.

Once Pages is live, the editor also runs at `https://<pages-base>/editor/` — handy for showing Lisa a section with real copy before anything touches AEM.

## Content lifecycle (the hybrid)

| Phase | Where copy lives | Who edits | AEM embed points at |
|---|---|---|---|
| **Design** | `sections/<name>/content.json` (repo) | Dustin, in the editor | `section.js` only — script falls back to the repo JSON |
| **Live** | `<DAM>/sections/<name>.json` | Marketing team, in AEM DAM | `section.js` + `data-content="<DAM json url>"` |

`section.js` resolves content in that order: `data-content` attribute if present, else `./content.json` next to the script. Nothing else changes between phases — same script, same markup.

### Promoting a section to live

1. In the editor → **Ship it** → *Download content.json*.
2. Upload it to the DAM folder (default `/content/dam/ameristar/com/us/en/sections/<name>.json`) and publish the asset.
3. Merge `main` → `prod`. GitHub Pages serves `prod`, so design changes never go live by accident.
4. In AEM, paste the **Content from DAM** snippet into the Embed component. Publish.

After that: copy changes = edit the DAM JSON (no GitHub). Design changes = edit the repo, merge to `prod`.

## Embedding in AEM

Two snippets, both generated by the editor:

**Script injection (preferred)** — renders into the page DOM, inherits fonts/width, auto-heights, crawlable.

```html
<div data-ameristar-section="audience-cards" data-content="https://www.ameristarperimeter.com/content/dam/ameristar/com/us/en/sections/audience-cards.json"></div>
<script src="https://ameristarwebdev.github.io/sections/sections/audience-cards/section.js" defer></script>
```

**iframe (fallback)** — fully isolated. Use for Leaflet-type widgets or if the Embed component won't execute `<script>`.

```html
<iframe id="ams-audience-cards" src="https://ameristarwebdev.github.io/sections/sections/audience-cards/index.html?content=…" title="Audience cards" loading="lazy" style="width:100%;border:0;display:block"></iframe>
<script>addEventListener("message",function(e){var m=e.data;if(m&&m.type==="ams:height"&&m.name==="audience-cards"){var f=document.getElementById("ams-audience-cards");if(f)f.style.height=m.height+"px"}})</script>
```

> **Verify once:** OneCMS base64-encodes component content and decodes it client-side. If the Embed component injects via `innerHTML`, inline `<script>` tags won't execute and you'll need the iframe variant. Test on a staging page before committing to script mode.

## Adding a section

1. Copy `sections/_template/` to `sections/<name>/` (kebab-case).
2. In `section.js` and `index.html`, change `NAME` / `_template` to `<name>`.
3. Write `schema.json` (fields the editor shows) and `content.json` (starting copy).
4. Add it to `sections/index.json`.
5. Open the editor and design.

### Schema field types

| type | notes |
|---|---|
| `text`, `url` | single line |
| `textarea` | multi-line |
| `select` | `"options": [...]` |
| `list` | repeating group: `"fields": [...]`, optional `min`, `max`, `itemLabel` (which sub-field to show as the row title) |

### Section rules (non-negotiable — they're what keep this embeddable)

- Vanilla JS, no build step, no framework, no npm.
- Every selector scoped under `.ams-<name>`. No global CSS, no `body`/`html` rules.
- No font loading in `section.js` — the AEM page already has Open Sans / Archivo. (`index.html` loads them for standalone preview only.)
- Escape every string from JSON (`esc()` is in the template). Content editors will paste whatever.
- Theme tokens: action `#006495`, active `#034b70`, accent `#00a0d0`.
- `render(root, data)` must be a pure function of its inputs — the editor calls it on every keystroke.

## Branches

- `main` — design work. The editor runs here.
- `prod` — what GitHub Pages serves. Only merged, approved sections.

Set Pages → Source → `prod` branch, root folder.

## Exceptions to "sections, not pages"

True app pages (product catalog, territory map) are one big section. They still live inside an AEM page shell — header, footer, nav and metadata come from AEM; the embed fills the body.
